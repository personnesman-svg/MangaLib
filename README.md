# Manga Platform

Проект-заготовка манга-библиотеки на **React + TypeScript + Vite + Ant Design**, **Laravel 12 / PHP 8.4**, **MySQL 8.4**, Nginx и Docker Compose. Каталог изначально пустой: никаких сидеров с выдуманными тайтлами, главами, пользователями или обложками.

## Что реализовано в исходниках

- Тёмный адаптивный UI: каталог, фильтры по названию/статусу/жанру/типу, сортировка, страница тайтла.
- Laravel API с пагинацией, опубликованные тайтлы/главы отделены от черновиков.
- Регистрация и вход через Sanctum stateful SPA cookies, CSRF-защита и роли `user`, `author`, `admin`.
- Заявка на статус автора с псевдонимом, портфолио и описанием планов; администратор одобряет или отклоняет её с комментарием.
- Кабинет автора: управление только собственными тайтлами и главами. Новые тайтлы и главы остаются неопубликованными до проверки администратора; автор не может публиковать их самостоятельно.
- Админка показывает очередь заявок авторов, авторов-заявителей и статус модерации; администратор может одобрить/отклонить заявку или тайтл и публиковать/снимать главы с публикации.
- Админка: создание/редактирование/удаление тайтлов, жанры, обложка; создание глав с несколькими изображениями; публикация с проверкой наличия страниц. Загрузка ограничена 30 изображениями на один запрос (по 15 МБ каждое); большие главы добавляются несколькими партиями.
- Чтение главы: вертикальный и постраничный режим, переход между главами, сохранение прогресса для авторизованного пользователя.
- Закладки, история чтения, комментарии и ответы на комментарии в API.
- Docker build для frontend/backend, Nginx, MySQL persistent volume, файловый volume; production-override с Caddy и автоматическим HTTPS.

## Локальный запуск

1. Установи Docker Engine и Docker Compose plugin.
2. Скопируй конфигурацию и сгенерируй ключ:

```bash
cp .env.example .env
# Создай ключ:
docker run --rm php:8.3-alpine php -r 'echo "base64:".base64_encode(random_bytes(32)).PHP_EOL;'
# Скопируй вывод в APP_KEY в .env; замени обе пароля БД на сильные уникальные значения.
```

3. Запусти сборку и контейнеры:

```bash
docker compose up --build -d
```

4. Создай схему БД (не заполняя контентом):

```bash
docker compose exec backend php artisan migrate --force
```

5. Создай администраторский аккаунт — пароль вводится интерактивно и не хранится в командной строке:

```bash
docker compose exec backend php artisan manga:admin-create admin@example.com "Site Admin"
```

6. Открой `http://localhost:8080`, войди и перейди в «Админка». Добавь свой первый тайтл, затем главу и страницы. БД после `migrate` содержит только схему, не контент.
7. Для авторской регистрации обычный пользователь открывает меню аккаунта → «Стать автором», отправляет заявку и ждёт решения. Администратор рассматривает её вверху страницы «Админка». После одобрения нужно обновить сессию/войти заново; появится «Кабинет автора».
8. Автор отправляет тайтлы на модерацию из кабинета. Администратор одобряет тайтл, а главы проверяет через «Главы» и публикует отдельно. Редактирование уже опубликованного авторского тайтла временно снимает его с публикации до повторного одобрения.

Для frontend-разработки с HMR можно запустить `cd frontend && npm install && npm run dev`; Vite проксирует `/api`, `/sanctum` и `/storage` в локальный Docker-сайт на `http://localhost:8080`.

## Production VPS с доменом и HTTPS

1. Настрой DNS A/AAAA записи своего домена на IP VPS, открой TCP 80/443 и UDP 443 в firewall.
2. Скопируй `.env.prod.example` в `.env`; задай реальный домен в `DOMAIN`/`APP_URL`, `SANCTUM_STATEFUL_DOMAINS` (домен без схемы, при необходимости `www.`), сгенерируй свой `APP_KEY` и уникальные пароли БД. Не используй `.env.example` со значениями localhost на продакшене.
3. Запусти prod-конфигурацию, которая не публикует порт Nginx напрямую и использует Caddy для TLS:

```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml up --build -d
docker compose exec backend php artisan migrate --force
docker compose exec backend php artisan manga:admin-create admin@your-domain.com "Site Admin"
```

Caddy автоматически выпустит TLS-сертификат для домена при корректном DNS и доступных портах 80/443. Не запускай одновременно dev override в production.

## Резервное копирование

Создать локальную копию MySQL и всех загруженных изображений: `bash scripts/backup.sh`. По умолчанию архив окажется в `backups/`; затем синхронизируй каталог в S3/другой сервер или другое off-site хранилище. Секреты из `.env` не добавляй в архив и репозиторий. Скрипт требует, чтобы контейнеры уже были запущены.

## Важные команды

```bash
docker compose logs -f backend nginx db
docker compose exec backend php artisan migrate:status
docker compose exec backend php artisan optimize:clear
```

## Данные и резервное копирование

`mysql_data` хранит MySQL; `manga_uploads` хранит обложки и страницы. Не выполняй `docker compose down -v` на сервере — это удалит именованные тома. Настрой автоматический **off-server** бэкап базы и файлов, периодически проверяй восстановление. Обновление контейнера само по себе не должно удалять эти тома.

Пример логического бэкапа БД (сохраняй файл вне VPS):

```bash
docker compose exec -T db sh -c 'exec mysqldump -u root -p"$MYSQL_ROOT_PASSWORD" "$MYSQL_DATABASE"' > manga-db.sql
```

Файлы манги также надо регулярно архивировать с volume `manga_uploads` и хранить отдельно от сервера.

## Честный статус

Это существенно расширенный рабочий каркас с API и основной логикой, но **до публичного production-релиза необходимо пройти интеграционные проверки на Docker-хосте**, протестировать регистрацию/сессии в браузере, многофайловую загрузку, обработку ошибок и права доступа. Рекомендуется добавить CI-тесты, мониторинг, rate limiting для всех публичных операций, политику модерации, ограничение размера/количества изображений на уровне бизнеса, а также проверку восстановления из резервных копий. Контент добавляется владельцем через админку, автоматического наполнения нет.
